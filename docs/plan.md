# Plan

## How the work is split

Two hours a day, one phase per session where a phase fits, written up before it
is built. Each phase gets a spec in `.claude/specs/` first: what it changes,
what the server enforces, what the tests are, and what "done" means. Writing the
spec first is what stopped me retrofitting `due_since` and the service cycle
identifier later, which would have meant a migration over data that had already
been recorded wrong.

| # | Session | Estimated | Actual | Outcome |
|---|---|---|---|---|
| 1 | Repo setup and walking skeleton | 2h 00 | 2h 20 | Done, minus deployment |
| 2 | Database schema and migrations | 1h 00 | 1h 30 | Done |
| | **Running total** | **3h 00** | **3h 50** | of a 12h budget |

## Order, and why

1. **Repository shape.** The project was sitting one directory below the git
   root inside an unrelated repo. Fixing that first meant every later commit
   landed in the repository that actually gets submitted.
2. **Walking skeleton.** API, database, migration, tests and a page that renders
   one row read through the whole stack. It satisfies no goal on its own, and it
   is the thing every goal depends on.
3. **Schema.** All seven tables in one migration, including `audit_events` and
   the cycle identifier. Everything else waits on this.
4. **Authentication next**, because the rest of the system is defined by what
   each role may do, and building endpoints before there is a role to check them
   against means writing them twice.

Tests go in the same session as the rule they cover. There is no testing phase
at the end. The lifecycle, odometer and authorization tests are the ones that
show judgement and they would be the first thing cut if they were left to last.

## Estimated versus actual

Session 1 ran 20 minutes over. The overrun was not the code. It was the shadcn
CLI, whose `init` now either scaffolds a new project or silently does nothing in
an existing one, so I wrote the three files it would have generated by hand. The
backend, including tests, came in roughly as expected.

Session 2 ran 30 minutes over, all of it on getting PostgreSQL running locally.
The winget package installed `bin/` without `lib/`, so `initdb` failed on a
missing `dict_snowball` library and there was no cluster and no service. I
switched to the standalone binaries zip, initialised a cluster under my own home
directory, and had both databases up a few minutes later. Writing the schema
itself was quick because the spec had already settled the awkward parts.

## What got cut, and what got moved

Nothing has been cut from the ten goals.

Deployment moved. The plan had it as phase 2, on the reasoning that discovering
a broken deployment at hour 11 is how this kind of project fails. I moved it to
the end of the build at my own decision, and the trade-off is written up in
`decisions.md`. The mitigation is that the deployment work is already done as
far as it can be without accounts: `render.yaml` is committed, configuration is
entirely environment-driven, and the frontend never hard-codes a host.

If time runs short later, the order I will cut in is: Playwright end-to-end
tests first (they are explicitly optional), then UI polish and loading-state
refinement, then CSV export conveniences while keeping the export itself.
Server-side authorization, lifecycle validation, due and overdue correctness,
the audit trail, and per-row bulk reporting do not get cut.
